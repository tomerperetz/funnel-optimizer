# Campaign Initialization Workflow — Product Specification

> Last updated: 2026-02-09
> Status: Draft — awaiting review

## Purpose

This document codifies the campaign initialization workflow: every section of the campaign plan report, every calculation, every validation rule, and the full operator workflow from "new client" to "campaign live." It eliminates ad-hoc variation between agent runs by defining exactly what is deterministic, what is rule-based, and what requires AI assistance.

---

## 1. Campaign Plan Report Specification

The campaign plan report is the primary output of the init workflow. It is an HTML document that an operator reviews before approving a campaign. Every report MUST contain the sections below, in this order.

### Section Inventory

| # | Section | Category | Data Source | Notes |
|---|---------|----------|-------------|-------|
| 1 | Header & Status Badge | Deterministic | Config + system state | Dry-run vs live, version |
| 2 | Campaign Overview (KPIs) | Deterministic | Config math | Budget, CPL, lead estimates |
| 3 | Validation Alerts | Rule-based | Config + rules engine | Blockers, warnings, recommendations |
| 4 | Revenue Projections (Dual ROI) | Deterministic + Configurable | Config + tenant defaults | Call center ROI + client ROI |
| 5 | Campaign Structure Tree | Deterministic + AI-assisted | Config + agent decisions | CBO, ad sets, ads, naming |
| 6 | Media Library | Deterministic + AI-assisted | Config images + visual analysis | Image inventory, usage assignments |
| 7 | Ad Previews (Facebook Mock) | AI-assisted | Config + generated copy | Full ad mock with copy, image, CTA |
| 8 | Campaign Configuration | Deterministic | Config fields | Customer, service, geo, details |
| 9 | Targeting | Deterministic | Config fields | Geo, age, interests, restrictions |
| 10 | Schedule | Deterministic | Config fields | Days, hours, dates, timezone |
| 11 | Lead Form | Deterministic | Config fields | Questions, privacy policy, thank-you |
| 12 | Experiment Design | Deterministic | Config + statistical math | Power calc, leads needed, cost, duration |
| 13 | Next Steps | Deterministic | System state | Ordered action items |
| 14 | Resume Editing Button | Deterministic | Config JSON embedded | Opens form pre-filled with config |
| 15 | Footer | Deterministic | Metadata | Timestamp, version, tenant info |

### Category Definitions

**Deterministic** — Calculated from config data using fixed formulas. Always produces the same output for the same input. Must be implemented in code, not generated by agent.

**Rule-based** — Derived from a defined set of rules applied to config data. Rules are enumerated in Section 5 of this document. New rules require a product decision and code change.

**AI-assisted** — Requires intelligence: ad copy generation, image-to-variant matching based on visual content, campaign structure recommendations. The agent provides these, but within a defined output schema.

### 2.1 End-to-End Flow

```

    |       |
    v       v
[5a] Fix   [5b] Approve
Issues      |
    |       v
    v   [6] Run Pipeline (creates DB records)
[2] Resume      |
    Form        v
            [7] Agent: Generate Final Report (with DB IDs)
                |
                v
            [8] Operator: Approve Content Variants
                |
                v
            [9] Connect Facebook Page (if new customer)
                |
                v
            [10] Create PAUSED Campaign on Meta
                |

            [11] Operator: Final Review on Meta
                |
                v

                |
                v
```

### 2.2 Step Details

#### Step 1: New Client Onboarding
**Actor:** Operator
**System:** Campaign Init Form (`reports/campaign-init-form.html`)
**Inputs:** Client name, service type, geo, budget, images, value propositions
**Output:** Filled form ready for export
**Decision point:** None — pure data entry

#### Step 2-3: Fill Form & Export Config
**Actor:** Operator
**System:** Campaign Init Form (client-side)
**Validation:** Form validates required fields (name, category, geo, daily budget, target CPL, 2+ value propositions)
**Output:** `CampaignConfig` JSON file

#### Step 4: Generate Campaign Plan Report (Dry Run)
**Actor:** Agent (or pipeline)
**Input:** Config JSON
**Output:** HTML report with "Dry Run" badge. No DB records created.
**Key distinction:** Dry run reports do NOT show DB IDs, approval commands, or campaign create commands. They show "Run init-campaign" as the next step.
**What the agent adds beyond deterministic report:**
- Ad copy (headline, primary text, description) for each variant
- Image-to-variant matching with rationale
- Campaign structure recommendation (CBO vs ABO, ad set grouping)
- Image analysis (dimensions, content description, suitability)

#### Step 5: Review & Fix Loop
**Actor:** Operator
**Decision points:**
- Are there blockers? (Must fix before proceeding)
- Are warnings acceptable? (Can proceed but should address)
- Is the ad copy good? (Subjective review)
- Are images appropriate? (Subjective review)

**If issues found:** Click "Edit Config in Form" button. Config is loaded back into the form via `localStorage`. Operator fixes issues and re-exports. Returns to Step 4.

**Resolved issues:** When a config is revised, the new report should show a "Resolved from Previous Review" section listing what was fixed. The agent tracks this by comparing the current config to the config embedded in the previous report.

#### Step 6: Run Pipeline
**Actor:** Operator (via CLI) or Agent
**Command:** `funnel campaign init <config.json>`
**Creates:**
- Customer record (find or create by name, case-insensitive)
- Brief record (with full config JSON stored)
- Content records (one per value proposition, all `status=draft`)
**Output:** `InitCampaignResult` with customer_id, brief_id, content_ids, report_path

#### Step 7: Generate Final Report
**Actor:** Pipeline code
**Key difference from dry run:** Includes DB IDs, approval commands, campaign creation commands
**Current gap:** The pipeline's `generate_campaign_plan_report()` produces a minimal report. The rich report (ROI, ad mocks, structure tree) is agent-generated. This document specifies what the pipeline report MUST include.

#### Step 8: Approve Content Variants
**Actor:** Operator
**Command:** `funnel content approve <id>` (one per variant)
**Precondition:** Report reviewed, all blockers resolved
**Effect:** Content status changes from `draft` to `approved`

#### Step 9: Connect Facebook Page
**Actor:** Operator (first time per customer only)
**Command:** `funnel auth start`
**Precondition:** Customer exists in DB with `meta_page_id=pending`
**Effect:** OAuth flow links Facebook Page, stores long-lived page token in DB
**Skip if:** Customer already has a valid page token

#### Step 10: Create PAUSED Campaign on Meta
**Actor:** Operator
**Command:** `funnel campaign create <content_id>` (one per approved variant)
**Precondition:** Content status = `approved`, customer has valid page token
**Creates on Meta:** Campaign -> Lead Form -> Ad Set -> Creative -> Ad (all PAUSED)
**Creates in DB:** Campaign record with meta IDs

#### Step 11: Final Review on Meta
**Actor:** Operator
**System:** Meta Ads Manager
**Review:** Verify campaign looks correct, preview ad, check targeting
**Optional but recommended**

#### Step 12: Activate Campaign
**Actor:** Operator
**Command:** `funnel campaign activate <campaign_id>`
**Effect:** Campaign + Ad Set status set to ACTIVE on Meta. Campaign status updated in DB.
**Safety rule:** This is always a manual action. No auto-activation.

#### Step 13: Monitor
**Actor:** System (scheduled) or Operator (manual)
**Commands:** `funnel leads collect`, `funnel leads metrics`
**Cadence:** Phase 1 manual, Phase 2A scheduled (cron)
**Guardrails:** Auto-pause if CPL > max_cpl_dollars (Phase 2D)

## 3. Configurable Parameters

### 3.1 Tenant-Level Settings (Call Center)

Settings that apply to ALL customers managed by this tenant. Stored in environment / settings table.

| Parameter | Current Location | Default | Configurable? | Notes |
|-----------|-----------------|---------|---------------|-------|
| Meeting price ($) | Not stored | $300 (hardcoded in agent reports) | **Must be configurable** | Drives all ROI calculations |
| Default close rate (%) | Not stored | 10% (hardcoded in agent reports) | **Must be configurable** | Base case for client ROI |
| Conservative close rate (%) | Not stored | 5% (hardcoded) | **Must be configurable** | Low scenario |
| Optimistic close rate (%) | Not stored | 15% (hardcoded) | **Must be configurable** | High scenario |
| Privacy policy URL | `FO_PRIVACY_POLICY_URL` | Empty | Yes | Fallback for customers without own URL |
| Meta app credentials | `.env` | Empty | Yes | Per-tenant Meta app |
| Ad account ID | `FO_META_AD_ACCOUNT_ID` | Empty | Yes | Single ad account per tenant |
| Default timezone | Not stored | America/Chicago | Should be configurable | Form default |
| Default operating hours | Not stored | 08:00-18:00 | Should be configurable | Form default |
| Default operating days | Not stored | Mon-Fri | Should be configurable | Form default |
| Report branding | Not stored | "Funnel Optimizer" | Future | White-label (Phase 4) |

**Action required:** Add `meeting_price_dollars`, `default_close_rate`, `conservative_close_rate`, `optimistic_close_rate` to `Settings` or a new tenant config.

| Parameter | Current Location | Notes |
|-----------|-----------------|-------|

| Facebook Page ID | `customers.meta_page_id` | Set via OAuth |
| Page access token | `customers.meta_page_access_token` | Set via OAuth |
| Website URL | `config_json.customer.website_url` | Optional |
| Business description | `config_json.customer.business_description` | Used for AI copy |

| Avg ticket ($) | `config_json.service.avg_ticket_dollars` | Drives client ROI calculation |

### 3.3 System Defaults (Hardcoded Until Proven Wrong)

Values that should NOT be configurable yet. Change only via code after data proves a better default.

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| Min daily budget warning | $20/day | Meta learning phase threshold |
| Min value propositions | 2 | Required for A/B testing |
| Default bid strategy | lowest_cost | Safest for new campaigns |
| Default optimization goal | LEAD_GENERATION | Only relevant goal for lead gen |
| Statistical confidence | 95% (p < 0.05) | Industry standard |
| Statistical power | 80% | Industry standard |
| Default min detectable effect | 25% | Reasonable for small-budget campaigns |
| Conversion estimate (p) for power calc | 0.5 | Conservative (maximizes sample size) |
| Housing min radius | 15 miles | Meta policy |
| Max CPL multiplier (auto-pause) | 2x target | Safety default |
| Image size recommendation | 1080x1080 or 1080x1350 | Meta feed ad specs |
| Min image size | 600x600 | Meta minimum requirement |

### 4.2 Campaign Overview (KPIs)

All calculations deterministic. Must match exactly across runs.

| KPI | Formula | Display |
|-----|---------|---------|
| Daily Budget | `config.budget.daily_dollars` | `$X` |
| Monthly Cap | `config.budget.monthly_cap_dollars` or `daily * 30` | `$X` |
| Total Spend | `daily * campaign_duration_days` if dates set; else monthly cap | `$X` |
| Target CPL | `config.budget.target_cpl_dollars` | `$X` |
| Max CPL | `config.budget.max_cpl_dollars` or `target * 2` | `$X` |
| Est. Leads/Day | `floor(daily / target_cpl)` | Integer |
| Est. Total Leads | `floor(total_spend / target_cpl)` | Integer |
| Campaign Duration | `(end_date - start_date).days` if both set; else "Ongoing" | `Xd` or "Ongoing" |
| Variant Count | `len(config.creative.value_propositions)` | Integer |

**Campaign duration calculation:**
```
if start_date AND end_date:
    duration_days = (end_date - start_date).days
    total_spend = min(daily * duration_days, monthly_cap)
elif start_date only:
    duration_days = None  # Ongoing
    total_spend = monthly_cap  # Show monthly projection
else:
    duration_days = None
    total_spend = monthly_cap
```

### 4.4 Revenue Projections (Dual ROI)

Two side-by-side boxes. All math is deterministic given configurable inputs.

#### Call Center ROI (left box, green accent)

| Row | Formula | Notes |
|-----|---------|-------|
| Estimated Leads | `est_total_leads` (from 4.2) | |
| Revenue | `est_leads * meeting_price` | `meeting_price` = tenant setting |
| Ad Spend | `-total_spend` | Negative (cost) |
| Net Profit | `revenue - total_spend` | Green if positive, red if negative |
| Margin | `(revenue - total_spend) / revenue * 100` | Percentage |
| ROI on Ad Spend | `(revenue - total_spend) / total_spend * 100` | Percentage |
| Profit per Lead | `meeting_price - target_cpl` | Quick unit economics |

#### Client ROI (right box, blue accent)

A table with three scenarios: Conservative, Base Case (highlighted), Optimistic.

| Column | Conservative | Base Case | Optimistic |
|--------|-------------|-----------|------------|
| Close Rate | `tenant.conservative_close_rate` | `tenant.default_close_rate` | `tenant.optimistic_close_rate` |
| Deals | `est_leads * close_rate` | | |
| Revenue | `deals * avg_ticket_dollars` | | |
| Pays Us | `est_leads * meeting_price` | | |
| Cost per Deal | `meeting_price * (1/close_rate)` | | (what client pays per closed deal) |
| Net | `client_revenue - pays_us` | | |
| ROI | `(client_revenue - pays_us) / pays_us * 100` | | |

**When `avg_ticket_dollars` is not set:** Show "N/A - set Average Ticket to see client ROI" instead of the table.

**When ROI is negative:** Display in red. This is a signal that meeting_price is too high or close rates are too low for this ticket size.

Display the meeting price prominently above the ROI boxes:

```

$260 profit/lead
$300 meeting price - $40 CPL
```

### 4.5 Campaign Structure Tree

**Category:** Deterministic structure + AI-assisted naming and grouping.

The deterministic part:
- Campaign level: CBO (Campaign Budget Optimization) at `daily_budget`, PAUSED
- One Ad Set per value proposition variant
- One Ad per Ad Set
- Lead Form shared across all ads (or one per ad, based on config)
- All under the same campaign objective (Lead Generation)
- Special ad category applied at campaign level

The AI-assisted part:
- Ad set naming (descriptive, based on the value proposition angle)
- Ad naming (angle label)
- Whether to use CBO vs ABO (default: CBO)
- Placement recommendation (default: Advantage+)
- Image-to-variant assignment rationale

**Output schema for agent:**
```json
{
  "campaign": {
    "name": "string — e.g., '{Customer} — {Service} — {Geo}'",
    "budget_optimization": "CBO",
    "objective": "Lead Generation",
    "special_ad_category": "HOUSING | null"
  },
  "ad_sets": [
    {
      "variant_label": "A",
      "name": "string — descriptive ad set name",
      "angle": "string — the value proposition angle in 2-4 words",
      "image_index": "int — which image from config.creative.image_urls to use",
      "image_rationale": "string — why this image matches this angle"
    }
  ],
  "shared_settings": {
    "targeting": "Broad / Advantage+",
    "placements": "Advantage+",
    "bid_strategy": "from config",
    "format": "Single Image with Lead Form"
  }
}
```

### 4.6 Media Library

**Category:** Deterministic inventory + AI-assisted analysis.

The deterministic part:
- Grid of all images from `config.creative.image_urls`
- Image index labels (Image 1, Image 2, ...)
- "Used in Ad X" / "Available" badges based on structure tree assignments

The AI-assisted part:
- Content description for each image (what the image shows)
- Dimension reporting (requires fetching image metadata)
- Suitability notes (landscape vs portrait, has logo, needs cropping)
- Format recommendation (crop to 1:1 or 4:5)

**Output schema for agent per image:**
```json
{
  "index": 1,
  "description": "string — what the image shows",
  "dimensions": "WxH",
  "orientation": "landscape | portrait | square",
  "used_in": "Ad A | null",
  "notes": "string — cropping advice, logo presence, etc."
}
```

### 4.7 Ad Previews (Facebook Feed Mock)

**Category:** AI-assisted (copy generation) + deterministic (layout).

The layout is a fixed Facebook feed ad mock with these slots:

| Slot | Source | Notes |
|------|--------|-------|
| Page avatar | First 2 letters of customer name | Deterministic |
| Page name | `config.customer.name` | Deterministic |
| "Sponsored" label | Fixed | Deterministic |
| Primary text | **AI-generated** | 3-4 sentences, matches brand voice, value prop angle |
| Image | From media library assignment | Deterministic once assigned |
| Headline | **AI-generated** | Max 40 chars, action-oriented |
| Description | **AI-generated** | Max 125 chars, trust signals |
| CTA button | `config.creative.cta` (human-readable label) | Deterministic mapping |
| Image choice rationale | **AI-generated** | Why this image for this variant |

**Output schema for agent per ad variant:**
```json
{
  "variant_label": "A",
  "angle": "string — 2-4 word angle name",
  "primary_text": "string — 3-4 sentences, uses brand voice",
  "headline": "string — max 40 chars",
  "description": "string — max 125 chars",
  "image_index": 1,
  "image_rationale": "string"
}
```

**Constraints on AI copy generation:**
- Must not use words in `config.creative.prohibited_words`
- Must match `config.creative.brand_voice`
- Must be in `config.creative.language`
- Must mention customer name at least once
- Must include a clear call to action matching the CTA button
- For Housing category: must not include discriminatory language (age, familial status, etc.)

### 4.12 Experiment Design

Deterministic statistical calculations.

| Field | Formula |
|-------|---------|
| Primary Metric | `config.experiment.primary_metric` |
| Variants | `config.experiment.num_variants` |
| Min Detectable Effect | `config.experiment.min_effect_pct` |
| Power / Significance | Fixed: 80% / 95% |
| Leads per Variant | `ceil((2 * (1.96 + 0.84)^2 * 0.5 * 0.5) / (min_effect_pct / 100)^2)` |
| Total Leads Needed | `leads_per_variant * num_variants` |
| Est. Cost | `total_leads_needed * target_cpl` |
| Est. Duration | `ceil(total_leads_needed / est_leads_day)` |

**Note:** The current formula uses p=0.5 (conservative conversion estimate). This is correct for a first pass. When historical data is available (`config.context.historical_conversion_rate`), the formula should use that instead.

### 4.13 Next Steps

Context-dependent based on system state.

**Dry-run report:**
1. Fix remaining warnings (list specific items)
2. Process images (crop to Meta dimensions if needed)
3. Run init-campaign: `funnel campaign init "<config_file>"`
4. Approve & launch

**Post-init report (DB records exist):**
1. Review variants above
2. Approve each variant: `funnel content approve <id>` (one per variant)
3. Create PAUSED campaigns: `funnel campaign create <id>` (one per approved variant)
4. Activate when ready: `funnel campaign activate <campaign_id>`

**Resume editing button:**
Always present. Embeds the full `CampaignConfig` JSON in a `<script>` tag. On click, stores config in `localStorage` and opens `campaign-init-form.html`.

## 5. Validation & Warning Rules

### 5.1 Blockers (Cannot Proceed to Campaign Creation)

These prevent the pipeline from creating Meta campaigns. They should be resolved before running `funnel campaign init` or at minimum before `funnel campaign create`.

| ID | Rule | Condition | Message |
|----|------|-----------|---------|
| B1 | No privacy policy | `config.lead_form.privacy_policy_url` is null AND `FO_PRIVACY_POLICY_URL` is empty | "No privacy policy URL -- Meta requires one for lead forms. Must add before campaign creation." |
| B2 | No Facebook Page | Customer exists but `meta_page_id = 'pending'` AND attempting campaign create | "Customer has no connected Facebook Page. Run `funnel auth start` first." |
| B3 | Expired page token | Customer's `meta_page_access_token` fails Meta API check | "Facebook Page token expired or invalid. Re-authenticate with `funnel auth start`." |
| B4 | No value propositions | `len(config.creative.value_propositions) < 2` | "At least 2 value propositions required for A/B testing." |
| B5 | Zero budget | `config.budget.daily_dollars <= 0` | "Daily budget must be greater than $0." |
| B6 | No geo specified | `config.geo.value` is empty | "Service area is required." |
| B7 | No customer name | `config.customer.name` is empty | "Customer name is required." |

### 5.2 Warnings (Can Proceed But Flagged)

Operator can override. Displayed in amber.

| ID | Rule | Condition | Message |
|----|------|-----------|---------|
| W1 | No images | `config.creative.image_urls` is null or empty | "No images provided -- campaigns without images have significantly worse CPL." |
| W2 | Low daily budget | `config.budget.daily_dollars < 20` | "${X}/day is low -- Meta needs $20+/day to exit learning phase effectively." |
| W3 | Housing restrictions | `config.service.special_ad_category == 'HOUSING'` | "Housing category active -- age, gender, zip, and interest targeting are restricted by Meta." |
| W4 | Housing with zip targeting | `special_ad_category == 'HOUSING'` AND `config.geo.type == 'zip_codes'` | "Zip code targeting not allowed for Housing category. Use DMA or radius (15mi+) instead." |
| W5 | Housing with narrow radius | `special_ad_category == 'HOUSING'` AND `config.geo.radius_miles < 15` | "Housing category requires minimum 15-mile radius. Current: {X} miles." |
| W6 | Housing with interest targeting | `special_ad_category == 'HOUSING'` AND `config.targeting.interest_keywords` is set | "Interest targeting is restricted for Housing category ads. Keywords will be ignored by Meta." |
| W7 | No max CPL set | `config.budget.max_cpl_dollars` is null | "No auto-pause CPL ceiling set. Campaign will run without cost guardrails. Consider setting max CPL to 2x target (${X})." |
| W8 | Budget too low for variants | `monthly_cap < leads_per_variant * num_variants * target_cpl` | "Monthly budget insufficient for statistically significant A/B test. Need ${X} but cap is ${Y}. Consider reducing to 2 variants." |
| W9 | No website URL | `config.customer.website_url` is null | "No website URL. Lead form ads will use the privacy policy URL as the click-through link." |
| W10 | Missing thank-you message | `config.lead_form.thank_you_message` is null | "No thank-you message set. A callback time expectation (e.g., 'We'll call within 30 min') improves lead quality." |

## 6. ROI Model

### 6.1 Call Center Perspective ("Our Revenue")

The call center buys leads from Meta at CPL, then sells meetings to the client at meeting price.

```
Inputs:
  meeting_price     = tenant setting (default $300)
  target_cpl        = config.budget.target_cpl_dollars
  est_total_leads   = floor(total_spend / target_cpl)
  total_spend       = daily * duration_days (or monthly_cap)

Calculations:
  revenue           = est_total_leads * meeting_price
  ad_spend          = total_spend
  net_profit        = revenue - ad_spend
  margin_pct        = net_profit / revenue * 100
  roas_pct          = net_profit / ad_spend * 100
  profit_per_lead   = meeting_price - target_cpl
```

**Assumptions that are configurable:**
- Meeting price (tenant-level)
- All leads convert to meetings (simplification for Phase 1; lead-to-meeting rate is a Phase 2 metric)

**Assumptions that are fixed:**
- Revenue = leads * meeting_price (every lead is billed as a meeting)
- Cost = only ad spend (no labor/overhead in Phase 1 model)

### 6.2 Client Perspective ("Client Revenue")

The client pays the call center `meeting_price` per lead and closes a percentage of them at `avg_ticket_dollars`.

```
Inputs:
  avg_ticket        = config.service.avg_ticket_dollars
  meeting_price     = tenant setting
  est_total_leads   = from Section 4.2
  close_rates       = [conservative, base, optimistic] from tenant settings

Per scenario:
  deals             = est_total_leads * close_rate
  gross_revenue     = deals * avg_ticket
  pays_us           = est_total_leads * meeting_price
  cost_per_deal     = meeting_price / close_rate  (or: pays_us / deals)
  net               = gross_revenue - pays_us
  roi_pct           = net / pays_us * 100
```

**When to show client ROI:**
- Only when `avg_ticket_dollars` is set (>0)
- When not set, show placeholder: "Set Average Ticket Size to see client ROI projections"

**When client ROI is negative:**
- Possible when meeting_price is high relative to avg_ticket * close_rate
- Display in red as a signal to adjust pricing

### 6.3 Sensitivity Analysis (Future Enhancement)

Not in v1 of the report, but the model supports:
- What CPL makes this unprofitable? (`break_even_cpl = meeting_price`)
- What close rate does the client need to break even? (`break_even_close = meeting_price / avg_ticket`)
- What meeting price makes client ROI > 100%? (solve for meeting_price)
